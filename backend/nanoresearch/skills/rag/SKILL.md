# RAG Search

## 概述

RAG 工具用于检索知识库内容。知识库包含两类内容：

| 内容 | 说明 |
|------|------|
| 用户上传的文档 | PDF、Markdown 等用户手动上传的资料 |
| 历史研究报告 | 之前 deep research 自动生成的报告，生成后自动入库 |

研究报告和用户文档在同一个知识库中，按相关性统一排序，不需要区分 collection。

## 工具列表

| 工具 | 用途 |
|------|------|
| `kb_search` | 统一检索入口（推荐） |
| `kb_retrieve` | 自行控制多跳检索 |

## 使用示例

### 查询知识库内容
```
kb_search(query="RAG 的实现原理")
```

### 查询过往研究报告
```
kb_search(query="3DGS 的局限性")
```

## 参数说明

| 参数 | 说明 | 默认值 |
|------|------|--------|
| `query` | 查询内容（必填） | - |
| `kb_id` | 知识库 ID | 自动使用默认知识库 |
| `context` | 外部上下文，用于解析指代词 | - |
| `max_iterations` | 复杂查询最大检索轮数 | 5 |

## 工作原理

`kb_search` 内部实现：
1. **Dense 检索**：向量相似度搜索
2. **Sparse 检索**：BM25 关键词匹配
3. **RRF 融合**：合并两种检索结果，按相关性排序
4. **可选重排序**：使用 reranker 进一步优化

## 内联引用标注（重要）

当你**用 kb_search 检索到的内容**回答时，在引用到某来源的那句话末尾内联标注 `[^n]`：
- `n` 取该来源在 kb_search 返回结果 `citations` 数组里的 `index`（结果 JSON 中每条 citation 都带 `index`）。
- **只有确实引用了检索内容才标**；你自己的推断、常识、web 来源不标。
- 一句可标多个来源：`……因此性能更优[^1][^3]。`
- 必须用**确切格式 `[^n]`**（方括号 + 脱字符 + 数字），不要用 `[n]`、`(n)`、`【n】` 等其它写法。
- `n` 必须是 `citations` 里真实存在的 index；拿不准就不标。

## 何时使用

| 场景 | 推荐操作 |
|------|----------|
| 用户问"我的文档里说..." | `kb_search(query="...")` |
| 用户问"我们之前研究过 X 吗？" | `kb_search(query="X")` — 研究报告已在知识库中 |
| 用户问"上次关于 X 的结论是什么" | `kb_search(query="X 结论")` |
| 用户问"有什么相关的研究" | `kb_search(query="...")` |
| 需要深入了解某个话题 | **先查知识库，再决定是否 deep research** |

## 决策流程：遇到知识类问题怎么办？

**重要原则**：遇到需要查询知识的问题时，**先查一次知识库，再决定是否深度研究**。

### 决策树

```
用户提问
    │
    ▼
这是知识类问题吗？
（需要事实、原理、案例、对比等）
    │
    ├─► 否 → 直接回答 或 使用 web_search/web_fetch
    │
    └─► 是 → 先查知识库（kb_search）
              │
              ▼
         现有知识足够吗？
         （有高相关度的结果）
              │
              ├─► 是 → 直接基于现有知识回答
              │         （可引用来源，说明来自之前的研究）
              │
              └─► 否 → 调用 research 进行完整研究
                         （通过 spawn 后台执行）
```

### 为什么先查知识库？

| 方式 | 耗时 | 成本 | 适用场景 |
|------|------|------|----------|
| 先查知识库 | ~1-2s | 低 | 已有结论，直接回答 |
| 直接 research | 10-30min | 高 | 需要新研究 |

**示例**：
- 用户问："3DGS 相比 NeRF 有什么优势？"
  - `kb_search("3DGS 对比 NeRF 优势")` → 如果研究报告中有相关内容 → 直接回答
- 用户问："最新的大模型架构发展趋势？"
  - `kb_search("大模型架构发展趋势")` → 如果无相关内容 → 启动 research

## 与 Deep Research 的协作

### 重要：research 是耗时任务，必须后台执行

`research` 工具执行时间 10-30min，**必须通过 `spawn` 后台执行**，不能前台阻塞用户。

### 知识不足时的正确操作流程

当知识库查询结果不足时，按以下步骤操作：

**步骤 1：告知用户**

```
message("正在深度研究「{topic}」，预计 10-30 分钟，完成后通知您...")
```

**步骤 2：后台启动研究**

```
spawn(
    task="用 research 工具研究以下问题，完成后把完整报告发给用户：{用户的问题}",
    label="{简短标签}"
)
```

**步骤 3：主 Agent 直接返回**

告诉用户已启动后台研究，然后结束当前回复，不要等待。

### 完整示例

```
用户："2025 年大模型 Agent 有什么最新进展？"

Agent 执行：
1. kb_search("大模型 Agent 2025")
   → 无高相关结果
2. 知识不足 → 准备启动后台研究
3. 调用 message 告知用户："正在深度研究「大模型 Agent 最新进展」，预计 10-30 分钟..."
4. 调用 spawn 后台执行：
   spawn(
       task="用 research 工具研究「2025 年大模型 Agent 最新进展」，完成后把完整报告发给用户",
       label="Agent 研究"
   )
5. 回复用户："已启动后台研究，完成后会通知您。"
6. 主 Agent 结束本轮对话，不等待研究完成

--- 后台 subagent 执行 ---
subagent 收到任务后：
1. 调用 research(action="start", topic="...", depth="normal")
2. 等待研究完成（10-30min）
3. 把完整报告发给用户（自动通知）
```

### 错误做法

❌ **前台直接调用 research**：
```
research(action="start", topic="...")
# 这会阻塞用户 10-30min，体验很差
```

✅ **通过 spawn 后台执行**：
```
message("正在研究...")
spawn(task="用 research 工具研究...")
"已启动后台研究，完成后通知您。"
```

### 工具职责分工

| 工具 | 职责 |
|------|------|
| `kb_search` | 轻量查询（~1s），先查这个 |
| `message` | 告知用户状态 |
| `spawn` | 后台执行耗时任务 |
| `research` | 深度研究（由 subagent 调用） |

### 流程总结

```
知识类问题
    │
    ▼
kb_search（~1s）
    │
    ├─► 有答案 → 直接回答
    │
    └─► 无答案 → message 告知 + spawn 后台研究
                   │
                   └─► 主 Agent 返回，subagent 执行 research
```
